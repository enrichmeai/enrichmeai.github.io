Cybersecurity: thinking like a defender

The Security page is about building secure software. This page is about the wider field: how real attacks unfold, how organisations defend, detect and recover, and the people and roles involved. You do not need to become a specialist, but every engineer should understand the game being played against their systems.

How real attacks unfold

MITRE ATT&CK is a public knowledge base of attackers' tactics and techniques, based on real-world observations. Its Enterprise matrix (version 20.1) groups what attackers do into 15 tactics, roughly in the order an intrusion progresses:

Reconnaissance → Resource Development → Initial Access → Execution → Persistence → Privilege Escalation → Stealth → Defense Impairment → Credential Access → Discovery → Lateral Movement → Collection → Command and Control → Exfiltration → Impact

  • Attackers rarely need anything clever. A stolen password, an unpatched server, a misconfigured bucket or a convincing email is usually enough to start.
  • Every step is a chance to stop them. Defence is not one wall; it is noticing and blocking at many of these stages.
  • Use it practically: for each system you own, ask which techniques would work against it, and whether you would see them.

Defence in depth

  • Identity first: strong, phishing-resistant sign-in, least privilege, and removing access people no longer need.
  • Keep things patched and known: you cannot protect what you do not know you have. Keep an inventory of systems, software and data.
  • Segment: a breach in one place should not open everything else.
  • Assume breach: design so that one compromised laptop, account or service does limited damage.
  • Back up, offline: see "Backups and ransomware" on the Security page.

Detect and respond

  • Collect the right signals: sign-ins, admin actions, process and network activity, cloud audit logs.
  • Detection is a craft: write rules for behaviour attackers cannot easily avoid, test them, and tune out noise, so real alerts are not drowned.
  • Have an incident plan before you need it: who leads, who decides, how you contain (isolate a machine, revoke a credential), how you communicate, and when you call in help or the authorities.
  • Learn without blame afterwards, and fix the root cause, not just the symptom.

The people and roles

  • Blue team / security operations (SOC): watch, detect and respond.
  • Red team and penetration testers: attack, with written permission, to find weaknesses first.
  • Purple teaming: both sides together, turning each attack into a detection.
  • Application and cloud security engineers: help builders get it right from the start (see Security).
  • Governance, risk and compliance: policies, audits and standards (see "Compliance frameworks" on the Security page).
  • Threat intelligence: who is attacking whom, and how.

Ethics and the law

  • Only test systems you own, or have written permission to test. Scanning or probing someone else's systems without permission is illegal in many countries, whatever your intent.
  • Practise legally: deliberately vulnerable training apps, capture-the-flag events and your own home lab.
  • Report what you find responsibly: through the organisation's security contact or vulnerability disclosure programme, and give them time to fix it.

Security is a team sport. The best defence is ordinary engineers who patch, review, log, ask "what if this is stolen?", and report mistakes quickly.

Levels: what to expect

1 Foundation

  • Explain how a typical intrusion unfolds
  • Spot phishing and report incidents quickly
  • Know that you only test systems you may test

2 Practitioner

  • Map your system's exposure to common attacker techniques
  • Log the signals an investigation needs
  • Follow the incident plan during an incident

3 Senior

  • Write and tune detections; run a tabletop exercise
  • Lead containment and recovery in an incident
  • Design defence in depth for a product

4 Expert

  • Own the organisation's security operations and incident response
  • Run red, blue and purple team programmes
  • Build a security culture across teams

Each level includes the ones before it. See Start here for what the levels mean.
