Data engineering on AWS

The same lifecycle as Data on GCP and Data on Azure, on Amazon Web Services: land, process, store, serve and govern. The service names differ; the ideas in Data Engineering do not. GCP vs AWS vs Azure maps the services side by side.

Service map by lifecycle stage

Stream inKinesis Data Streams; Amazon MSK (managed Kafka)Events and change streams

A reference architecture

  1. Files and events land in an S3 raw prefix, never edited.
  2. A Glue crawler or job registers the schema in the Glue Data Catalog.
  3. Glue or EMR jobs write cleaned, partitioned Parquet or Iceberg tables to a curated prefix.
  4. Athena queries the curated tables directly; Redshift serves heavy, repeated BI workloads.
  5. dbt models the curated layer into products (dbt has Athena and Redshift adapters). See dbt.
  6. Lake Formation grants each team only the tables and columns it needs.

Choosing between similar services

  • Athena or Redshift? Athena for ad-hoc SQL on files, paid by data scanned. Redshift for a warehouse with steady, heavy queries and many users.
  • Glue or EMR? Glue for serverless Spark jobs without managing clusters. EMR when you need control of the cluster, other engines, or long-running jobs.
  • Kinesis or MSK? Kinesis for AWS-native streams with little to run. MSK when you want Kafka's API, tools and portability. See Kafka.
  • MWAA or Step Functions? Airflow for data pipelines with many dependencies; Step Functions for event-driven workflows across AWS services.

Handy commands

The AWS CLI calls the same APIs the console does. Names in angle brackets are yours to fill in.

# copy a file into the lake's raw prefix
aws s3 cp orders.csv s3://<bucket>/raw/orders/dt=2026-11-14/

# register its schema, then run a Glue job
aws glue start-crawler --name <crawler>
aws glue start-job-run --job-name <job> --arguments '{"--run_date":"2026-11-14"}'

# query it with Athena, then fetch the results
aws athena start-query-execution --work-group primary \
  --result-configuration OutputLocation=s3://<bucket>/athena-results/ \
  --query-string "SELECT status, count(*) FROM shop.orders GROUP BY status"
aws athena get-query-results --query-execution-id <id-from-above>

# run SQL on Redshift Serverless without a JDBC driver
aws redshift-data execute-statement --workgroup-name <wg> --database dev \
  --sql "SELECT count(*) FROM orders"

# put one event on a Kinesis stream
aws kinesis put-record --stream-name orders --partition-key a1 --data <data>

Each operation and parameter was checked against the AWS SDK's service definitions (botocore).

IAM for data, in practice

  • Roles, not keys: jobs run as IAM roles; people sign in through single sign-on. No long-lived access keys in code.
  • Two layers: IAM decides who may call a service; Lake Formation decides which databases, tables, columns and rows they may read.
  • Separate raw from curated with different prefixes or buckets and different grants.
  • Block public access on every data bucket, and encrypt with KMS keys you control.

Cost controls

  • Athena bills by data scanned: Parquet or Iceberg, partitions and selecting only the columns you need cut it sharply. Workgroups can cap a query's scan.
  • S3 lifecycle rules move old raw data to cheaper storage classes.
  • Pause or size Redshift and EMR to the workload; serverless options bill only while they run.
  • Budgets and tags per team and pipeline, so a cost has an owner.

Levels: what to expect

1 Foundation

  • Name the AWS service for each data stage
  • Land files in S3 and query them with Athena
  • Explain IAM roles for data jobs

2 Practitioner

  • Build a pipeline: S3 raw, Glue, curated Parquet or Iceberg, Athena
  • Use Lake Formation to grant table access
  • Model with dbt on Athena or Redshift

3 Senior

  • Choose between Athena and Redshift, Glue and EMR, Kinesis and MSK
  • Design a governed data lake with a catalog
  • Plan cost, regions and data residency

4 Expert

  • Own the organisation's AWS data architecture
  • Lead migrations between clouds or from on-premises
  • Set data platform standards across teams

Each level includes the ones before it. See Start here for what the levels mean.
