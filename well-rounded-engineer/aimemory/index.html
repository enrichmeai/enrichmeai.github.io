AI memory and threads

Why a chatbot forgets, how assistants now remember across conversations, and how three of them, Claude (including Cowork), Microsoft 365 Copilot and Perplexity, organise threads, projects and memory, with what each lets you see, pause and delete.

The short answer

A language model on its own remembers nothing between requests. Every time you send a message, the app sends the model the conversation so far, and the model reads it all again; that working space is the context window (see LLMs). When a conversation, or thread, ends, nothing about it stays inside the model.

So “memory” in an AI assistant is always something the app builds around the model: it saves notes about you, keeps files in a project, or searches your old chats and documents, then puts the relevant parts back into the context window when you next ask. That is the same idea as retrieval on RAG, pointed at your own history. The interesting differences between products are what they store, where, and who controls it.

Claude: chat search, memory and projects

Anthropic’s help centre describes three separate mechanisms:

  • Chat search. On paid plans, Claude can search your past chats when you ask, for example “let’s continue where we left off”. It uses retrieval-augmented generation, and the search shows up as a tool call in the conversation. Chats inside a project only search that project.
  • Memory. Claude saves memory “as a set of individual topics as you chat, rather than summarizing conversations after they end”. It is on by default for individual plans; on Team and Enterprise plans the owners decide. You can pause it, which keeps what is saved but stops using or adding to it, or reset it, which permanently deletes everything, including project memories. By default it does not store sensitive topics such as health, religion or politics unless you turn that on.
  • Projects. Self-contained workspaces with their own chat history, files and instructions. Each project has its own memory; inside a project Claude uses that project’s memory plus your general memory, but never another project’s. When a project’s files approach the context window limit, Claude switches to retrieval automatically, which Anthropic says expands capacity by up to ten times.

For a single conversation that leaves no trace, there are incognito chats: they are not saved to your history, and Claude does not draw on them when searching past chats. You can also turn memory off for one chat from the “+” menu.

Claude Cowork: tasks instead of chats

Cowork is the mode where you hand Claude a multi-step task rather than a question. It changes what a “thread” is:

  • A task is the thread. Cowork runs the work in an isolated environment on Anthropic’s servers, and the session and its files are saved to your account, so you can start a task on one device and pick it up on another; work continues if you close your laptop. Claude breaks complex work into subtasks and can run parallel workstreams.
  • Long tasks are designed for. Anthropic describes Cowork as working on complex tasks for extended periods “without conversation timeouts or context limits interrupting your progress”.
  • One memory with chat. When Cowork runs in the cloud, it shares memory with ordinary chat in both directions: what Claude knows from your chats is there in a task, and what comes up in a task carries back. Sessions that run locally on your computer do not use memory. Whether a task uses memory is fixed when it starts.
  • Projects and schedules. Related tasks can be grouped into projects with their own files, instructions and memory, and scheduled tasks run in the cloud with no device online. A deleted task leaves your history at once and is removed from Anthropic’s storage within 30 days.

Microsoft 365 Copilot: memory in your mailbox, grounding in your organisation

Microsoft’s design starts from the organisation rather than the individual:

  • Grounding in Microsoft Graph. Copilot can draw on emails, chats and documents in Microsoft Graph that you already have permission to see, and only those. Microsoft’s advice follows from that: get SharePoint and Teams permissions right, because Copilot will surface whatever a user can open.
  • Threads are stored like other work data. Your prompts and Copilot’s responses, with citations, are stored as your Copilot activity history, processed and kept under the same commitments as your organisation’s other Microsoft 365 content. Microsoft says prompts, responses and Graph data are not used to train its foundation models.
  • Memory has three parts, in preview: saved memories, details inferred from chat history, and custom instructions. All are stored in a hidden folder in your Exchange mailbox, so they inherit the mailbox’s security, such as encryption at rest.
  • Each part lives differently. Saved memories stay until you delete them, and deleting a chat does not delete memories made from it. Inferred details disappear within seven days once every chat that mentioned them is deleted. If the feature is switched off, inferred details are deleted after 30 days, while saved memories and instructions are kept but not used.
  • Admins have the controls. Memory is on by default through the “Enhanced personalization” setting, which a tenant admin can switch off. Admins can find and delete users’ memories with Purview eDiscovery. One surprise worth knowing: Purview retention policies do not apply to Copilot memory, so a “delete after three months” rule for Copilot chats does not delete memories.

Perplexity: threads around search

Perplexity is an AI search engine; its leadership calls it an “answer engine”, and it stopped selling ads in February 2026, saying it wanted to keep users’ trust in the answers. What we could also confirm from independent sources: its Enterprise Pro plan lets an organisation upload and index up to 500 files, and its phone assistant, launched in January 2025, can keep context across actions such as booking a ride or finding a song.

We could not check Perplexity’s own documentation on memory, threads and Spaces: its help centre refuses automated reading. Rather than describe those features from memory, we leave them out until we can cite Perplexity directly. If you rely on its memory features, read its help centre before trusting this summary.

Choosing, by requirement

If this is true for youIt leans towards
Your work lives in Outlook, Teams and SharePoint, and IT must govern itMicrosoft 365 Copilot: memory and history sit inside your tenant’s compliance tools
You keep several unrelated streams of work that must not mixSeparate projects with their own memory (Claude), and checking that project memory is isolated
You hand off long, multi-step jobs and want to check in from your phoneA task-based tool such as Cowork, where the thread runs in the cloud
Your questions are mostly about current information on the webA search-first assistant such as Perplexity, built around web search
You handle sensitive personal topicsMemory off, or incognito, for those chats; and knowing whether deleting a chat deletes what was learned from it
Your organisation already pays for one of theseThat one, because switching costs time and data; learn its controls first

Our view, and the other view

Our view: memory is what turns a chatbot into a colleague, but only if you can see it, edit it and switch it off. Before relying on any assistant’s memory, find out three things: where it is stored, what deleting a chat really deletes, and who else can read it.

The other view: some prefer assistants that remember nothing, treating each conversation as a clean room: fewer surprises, less risk of an old mistake being repeated, and nothing to leak. The cost is repeating yourself, which is exactly what memory was built to remove.
