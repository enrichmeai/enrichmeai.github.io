Guide / Languages / Go

Go: simple, fast to build, made for services

Go is an open-source language for building simple, reliable and efficient software. It compiles to a single binary, starts fast, and has concurrency built in. Much of the cloud's own tooling is written in it, including Docker, Kubernetes and Terraform.

Where you meet it

  • Cloud and platform tools: Docker, Kubernetes, Terraform, Prometheus and many operators are written in Go. Reading Go helps you debug the tools you run. See Kubernetes and Operators.
  • Network services and APIs, where its small binaries and fast start-up suit containers.
  • Command-line tools, shipped as one file with no runtime to install.

The ideas that matter

  • Small on purpose: few keywords, one formatting style (gofmt), one obvious way to do most things.
  • Errors are values: functions return an error; you check if err != nil. Wrap with %w and test with errors.Is.
  • Goroutines and channels: cheap concurrent functions, coordinated with channels, sync.WaitGroup and mutexes.
  • Interfaces are implicit: a type satisfies an interface just by having its methods.
  • Composition, not inheritance: embed one struct in another.
  • A strong standard library: HTTP servers, JSON and testing need no framework.

A small program, and its test

go run . runs it; go test -race ./... runs the table-driven test with the race detector on. Both pass as written.

package main

import (
	"errors"
	"fmt"
	"sync"
)

type Order struct {
	ID    string
	Pence int
}

var ErrInvalid = errors.New("invalid order")

// Validate returns an error value instead of throwing: the caller must decide.
func Validate(o Order) error {
	if o.Pence <= 0 {
		return fmt.Errorf("order %s: %w", o.ID, ErrInvalid)
	}
	return nil
}

// Total validates orders concurrently, one goroutine each, and sums the valid ones.
func Total(orders []Order) (int, []error) {
	var (
		wg   sync.WaitGroup
		mu   sync.Mutex
		sum  int
		errs []error
	)
	for _, o := range orders {
		wg.Add(1)
		go func(o Order) {
			defer wg.Done()
			err := Validate(o)
			mu.Lock()
			defer mu.Unlock()
			if err != nil {
				errs = append(errs, err)
				return
			}
			sum += o.Pence
		}(o)
	}
	wg.Wait()
	return sum, errs
}

func main() {
	sum, errs := Total([]Order{{"a1", 1250}, {"a2", 0}, {"a3", 499}})
	fmt.Println("total pence:", sum)
	for _, e := range errs {
		fmt.Println("error:", e, "| invalid?", errors.Is(e, ErrInvalid))
	}
}
package main

import (
	"errors"
	"testing"
)

func TestValidate(t *testing.T) {
	cases := []struct {
		name    string
		order   Order
		wantErr bool
	}{
		{"positive amount", Order{"a1", 100}, false},
		{"zero amount", Order{"a2", 0}, true},
		{"negative amount", Order{"a3", -5}, true},
	}
	for _, c := range cases {
		t.Run(c.name, func(t *testing.T) {
			err := Validate(c.order)
			if (err != nil) != c.wantErr || (err != nil && !errors.Is(err, ErrInvalid)) {
				t.Fatalf("Validate(%v) = %v, wantErr %v", c.order, err, c.wantErr)
			}
		})
	}
}

Build and tools

  • Modules: go mod init, dependencies pinned in go.mod and go.sum.
  • Built in: go build, go test (with -race and -cover), go vet, gofmt, and benchmarks and fuzzing in the test tool.
  • Containers: a static binary fits a tiny base image. See Docker.

Common mistakes

  • Ignoring an error with _: the failure is silent until it is expensive.
  • Leaking goroutines: one blocked forever on a channel nobody reads. Pass a context.Context and stop on cancel.
  • Data races: shared state touched from goroutines without a lock or channel. Run tests with -race.
  • A nil map write panics: make the map first.

Levels: what to expect

1 Foundation

  • Write and run a small Go program
  • Handle errors as values
  • Write a table-driven test

2 Practitioner

  • Build an HTTP service with the standard library
  • Use goroutines, channels and context safely
  • Run tests with the race detector and coverage

3 Senior

  • Design packages and interfaces for a large codebase
  • Profile and tune with pprof
  • Read and debug cloud tools written in Go

4 Expert

  • Set Go standards across teams
  • Build operators or platform tooling in Go
  • Teach Go's concurrency model and review for it

Each level includes the ones before it. See Start here for what the levels mean.
