Robotics: software that moves things

A robot senses the world, decides what to do and acts on it, over and over, many times a second. Robotics joins electronics, mechanics, control theory and software, and mistakes move real objects near real people, so safety comes first.

Sense, think, act

  • Sense: cameras, lidar, encoders on the wheels and joints, inertial sensors, force and touch sensors.
  • Think: work out where the robot is, what is around it, and what to do next.
  • Act: motors and actuators turn decisions into movement.
  • The loop never stops: every sensor is noisy and every motor imperfect, so the robot measures again and corrects, all the time.

The core ideas

  • Control: a PID controller turns the error between where you are and where you want to be into a command. The example below shows each term at work.
  • Kinematics: forward kinematics asks where the hand is, given the joint angles; inverse kinematics asks which joint angles put the hand there. The second is the hard one.
  • Localisation and mapping (SLAM): building a map of an unknown place while keeping track of where you are in it, the problem self-driving cars and warehouse robots solve.
  • Planning: finding a path that avoids obstacles and respects what the robot can physically do.

A PID controller you can run

Plain Python. A toy motor with friction is driven to a target speed of 100. Proportional control alone settles short, because it needs an error to produce any power; the integral term removes that gap.

"""A PID controller holding a simple motor at a target speed."""
def simulate(kp, ki, kd, target=100.0, steps=200, dt=0.05):
    speed, integral, prev_error = 0.0, 0.0, target
    for _ in range(steps):
        error = target - speed                    # how far off are we?
        integral += error * dt                    # I: past error that has not gone away
        derivative = (error - prev_error) / dt    # D: how fast the error is changing
        prev_error = error
        power = kp * error + ki * integral + kd * derivative
        power = max(-100.0, min(100.0, power))    # real motors have limits
        speed += (power - 0.5 * speed) * dt       # toy physics: power pushes, friction resists
    return round(speed, 1)

print("P only:  ", simulate(kp=2.0, ki=0.0, kd=0.0))   # settles short of the target
print("PI:      ", simulate(kp=2.0, ki=1.0, kd=0.0))   # the integral removes the gap
print("PID:     ", simulate(kp=2.0, ki=1.0, kd=0.1))

PI:       100.1

The software stack: ROS 2

  • ROS (Robot Operating System) is open-source robotics middleware, not an operating system. ROS 2 is the current generation.
  • Nodes and topics: each part of the robot (a camera driver, a planner, a motor controller) is a node; nodes exchange messages over named topics. It is publish/subscribe, as in Kafka, on a robot.
  • Simulate first: test in a simulator before the real hardware, where a bug costs a crash in software rather than a broken arm.
  • Languages: C++ where timing matters, Python for tools and glue; Rust is growing.

Safety comes first

  • Standards exist for a reason: ISO 10218 is the international standard for industrial robot safety.
  • Emergency stop: every robot has one a person can reach, and it works even when the software does not. The manual override from Worried about AI?, made of hardware.
  • Fail safe: on lost signal, low battery or a sensor fault, stop or move to a safe state.
  • Test the bad cases in simulation and on the bench: a person stepping in, a sensor going dark, a motor stalling.

Where to start

Begin small and physical: a microcontroller, two motors, a distance sensor and a line to follow. Then add a PID loop, then a camera, then ROS 2 in a simulator. Robotics rewards the foundations: Mathematics (geometry, probability), Linux, Networking, and patient experiment. AI models are increasingly part of the "think" step, but the loop, the limits and the emergency stop stay the engineer's job.

Levels: what to expect

1 Foundation

  • Explain the sense-think-act loop
  • Tune a PID controller in simulation
  • Know why every robot has an emergency stop

2 Practitioner

  • Build a small robot or simulated one with ROS 2 nodes and topics
  • Read sensor data and filter its noise
  • Apply forward and inverse kinematics to an arm

3 Senior

  • Design localisation, mapping and path planning
  • Design for functional safety and failure modes
  • Move from simulation to hardware safely

4 Expert

  • Lead a robotics platform or product
  • Set safety and testing standards
  • Combine learned models with classical control responsibly

Each level includes the ones before it. See Start here for what the levels mean.
