Guide / Frontiers / Bitcoin & Blockchain

Bitcoin and blockchain, from first principles

How a blockchain works underneath, using Bitcoin as the example: hashes, linked blocks, proof of work and keys. Understand the mechanism before forming a view on the money. Smart contracts and the wider Web3 ideas are on Web 3.0.

The story in brief

  • 31 October 2008: a white paper by Satoshi Nakamoto, Bitcoin: A Peer-to-Peer Electronic Cash System, was posted to a cryptography mailing list.
  • 3 January 2009: the network started when the first block, the genesis block, was mined.
  • The problem it solved: how strangers can agree on who owns what, with no bank or central server in the middle, and without anyone spending the same coin twice.

How a blockchain works

  • Hashes: a hash is a short fingerprint of data. Change one character and the fingerprint changes completely. See Mathematics.
  • Linked blocks: each block holds transactions and the hash of the block before it, so changing an old block breaks every link after it.
  • Proof of work: to add a block, miners search for a number (a nonce) that makes the block's double SHA-256 hash fall below a target. Finding it costs a lot of computing; checking it costs one hash.
  • Consensus: thousands of independent nodes check every block and follow the chain with the most accumulated work. Rewriting history means redoing that work faster than everyone else combined.

Build a toy blockchain

Plain Python, standard library only. It mines three blocks, checks the chain, then tampers with a past transaction and shows the chain fail. The nonce it prints changes from run to run, because the timestamp does.

"""A toy blockchain: blocks linked by hashes, sealed by proof of work."""
import hashlib, json, time

def block_hash(block):
    data = json.dumps(block, sort_keys=True).encode()
    return hashlib.sha256(hashlib.sha256(data).digest()).hexdigest()  # double SHA-256, as Bitcoin does

def mine(prev_hash, transactions, difficulty=4):
    """Try nonces until the hash starts with `difficulty` zeros: costly to find, cheap to check."""
    block = {"prev": prev_hash, "tx": transactions, "time": int(time.time()), "nonce": 0}
    while not block_hash(block).startswith("0" * difficulty):
        block["nonce"] += 1
    return block

def valid(chain, difficulty=4):
    for prev, block in zip(chain, chain[1:]):
        if block["prev"] != block_hash(prev):
            return False                          # a link is broken
        if not block_hash(block).startswith("0" * difficulty):
            return False                          # no proof of work
    return True

genesis = mine("0" * 64, ["genesis"])
chain = [genesis]
chain.append(mine(block_hash(chain[-1]), ["alice pays bob 5"]))
chain.append(mine(block_hash(chain[-1]), ["bob pays carol 2"]))
print("valid:", valid(chain), "| nonce of block 2:", chain[2]["nonce"])

chain[1]["tx"] = ["alice pays bob 500"]          # tamper with history
print("after tampering:", valid(chain))          # every later link now breaks
valid: True | nonce of block 2: 116188
after tampering: False

Bitcoin's rules, in numbers

  • About 10 minutes per block on average; the difficulty adjusts so it stays there as miners come and go.
  • A fixed supply of 21 million bitcoin at most.
  • The mining reward halves every 210,000 blocks, roughly every four years.
  • Keys: an address is computed from a randomly generated private key. Computing the address is instant; finding the key from the address is practically impossible. Whoever holds the key controls the coins.

Trade-offs and risks

  • Energy: proof of work uses a great deal of electricity, and has been criticised for its environmental impact. Ethereum moved from proof of work to proof of stake in September 2022 ("The Merge"), cutting its energy use by over 99%.
  • No undo: a payment to the wrong address, or a lost key, is usually gone for good.
  • Scams thrive where payments are irreversible: fake investments, "recovery" services, impersonation. Nobody legitimate asks for your private key or seed phrase.
  • Volatility: prices can swing widely. This page explains the technology; it is not investment advice.

What engineers can take from it

Even if you never touch a cryptocurrency, the ideas travel: content-addressed data (Git commits are linked by hashes too, see DevOps), append-only logs (see Event Sourcing), public-key cryptography (see Security), and agreement between machines that do not trust each other. Ask the question on Web 3.0 first: do you actually need a blockchain, or a database with good audit logs?

Levels: what to expect

1 Foundation

  • Explain hashes and how blocks link
  • Explain proof of work and why rewriting history is hard
  • Keep keys safe and recognise common scams

2 Practitioner

  • Build a toy chain and validate it
  • Explain Bitcoin's supply, halving and difficulty rules
  • Compare proof of work and proof of stake

3 Senior

  • Judge whether a problem needs a blockchain at all
  • Design key custody and recovery
  • Assess the security model of a chain or protocol

4 Expert

  • Advise an organisation on distributed-ledger strategy
  • Review consensus and cryptographic designs
  • Explain the technology to non-specialists without hype

Each level includes the ones before it. See Start here for what the levels mean.
