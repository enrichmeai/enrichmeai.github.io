Claude Code and Claude Cowork

Claude Code is Anthropic's agentic coding tool: it reads your repository, edits files, runs commands and tests, and works through tasks with you or on its own. Claude Cowork brings the same agentic way of working to non-coding knowledge work in the Claude desktop app. How each is set up, extended and kept safe.

Where Claude Code runs

SurfaceUse it for

IDE extensions (VS Code, JetBrains)The same agent beside your editor, with diffs inline

Everyday commands

claude                              # start in the current repo
claude "fix the failing date parser test"
claude -c                           # continue the last conversation
claude -r                           # pick an earlier session to resume
claude -p "summarise this diff" --output-format json < diff.txt   # headless

# inside a session
/init        create a CLAUDE.md for this repo
/memory      edit memory files
/agents      manage subagents
/mcp         MCP servers and their status
/permissions view rules
/compact     summarise the conversation to free context
/clear       start fresh
Shift+Tab    cycle permission modes (incl. plan mode)
Esc          interrupt

The files that shape it

FileHolds
CLAUDE.md (repo root, subfolders)Project memory: what the system is, rules, commands, traps. Loaded every session.
~/.claude/CLAUDE.mdYour personal preferences across projects
.claude/settings.jsonShared permissions, hooks, environment, model settings (committed)
.claude/settings.local.jsonYour local overrides (not committed)

.claude/skills/<name>/SKILL.mdSkills: packaged procedures invoked by name or when relevant
.claude/commands/*.mdCustom slash commands
.mcp.jsonMCP servers shared with the team

These files are the blueprint for how agents work in your repo. Keep them short, specific and current; a stale rule misleads every session.

Permissions and hooks

// .claude/settings.json
{
  "permissions": {
    "allow": ["Bash(./gradlew test:*)", "Bash(git status)", "Bash(git diff:*)"],
    "deny":  ["Read(./.env)", "Bash(rm -rf:*)"]
  },
  "hooks": {
    "PreToolUse": [
      { "matcher": "Bash",
        "hooks": [{ "type": "command", "command": ".claude/hooks/guard-destructive.sh" }] }
    ],
    "PostToolUse": [
      { "matcher": "Edit|Write",
        "hooks": [{ "type": "command", "command": ".claude/hooks/check-edited-file.sh" }] }
    ],
    "Stop": [
      { "hooks": [{ "type": "command", "command": ".claude/hooks/stop-gate.sh" }] }
    ]
  }
}
  • Permission modes: default (ask), accept edits, plan (read and propose only), and fully autonomous modes for sandboxed environments.
  • Hooks run your scripts at events (before/after a tool, on prompt submit, at stop, at session start). A hook that exits with code 2 blocks the action where the event allows it (PreToolUse blocks the tool call, Stop prevents stopping) and its stderr is fed back to Claude. A PostToolUse hook runs after the tool, so exit code 2 only feeds stderr back.
  • Use hooks for rules that must always hold (lint after every edit, block pushes to main); use CLAUDE.md for guidance.

Subagents and skills

<!-- simplified example of .claude/agents/reviewer.md -->
---
name: reviewer
description: Independent reviewer of a finished diff before a PR is opened.
  Use at the end of every task.
tools: Read, Grep, Glob, Bash
model: sonnet
---
Review the diff against the task, CLAUDE.md and the official docs of every
library it touches. Report bugs, missing tests and unverified API use.
Do not edit files.
<!-- simplified example of .claude/skills/<name>/SKILL.md -->
---
name: release-sync
description: Bring a project page up to date with that project's latest
  release. Use after a release or when a sync issue is open.
---
1. Read the release tag and changelog.
2. Update the version markers and the "what's new" block.
3. Run the release checker until it reports 0 findings.

Subagents keep their own context, so a reviewer is not anchored on the builder's reasoning. Skills turn a procedure that cost a debugging cycle into something every session follows.

A worked example: an autonomous build loop

  1. /new-issue turns an idea into a ready issue.
  2. /build-task builds it: verify docs, write a failing test, implement.
  3. Hooks check every edit; a stop hook runs the full check before the turn can end.
  4. A reviewer subagent checks the finished diff independently.
  5. Fix what it finds, at most three attempts, then write a blocker summary instead of looping.
  6. /compound turns what went wrong into a permanent guard (a test, hook or rule).
  7. Open a PR; a human (or a gated merge skill) merges.

Each step is a skill, agent or hook committed to the repository, so every session follows the same loop.

Claude Cowork

Cowork applies Claude's agentic loop to everyday knowledge work rather than code: it works through multi-step tasks on your files, documents and connected apps from the Claude desktop app, and checks in with you as it goes.

Claude CodeClaude Cowork
Main usersEngineersAnyone doing knowledge work: analysts, operations, legal, sales, founders
Works onRepositories: code, tests, builds, GitFolders, documents, spreadsheets, presentations, connected apps
Extended byCLAUDE.md, skills, subagents, hooks, MCP, pluginsSkills, plugins and connectors (MCP), often packaged per role
Typical tasksImplement a feature, fix a bug, review a PR, run a migrationPrepare a report from files, reconcile spreadsheets, draft documents, run a recurring brief
  • Plugins bundle skills, commands, agents and connectors for a role or team, so the organisation's way of working is installed rather than re-explained.
  • Same rules as any agent: give it a clear brief and a definition of done, limit what it can access, and review what it produces before it is sent anywhere.
  • Features and availability change frequently; check Anthropic's current product documentation.

Working well with Claude Code

  • Plan first for anything non-trivial: plan mode, read the plan, then let it build.
  • Give it a way to check itself: exact test and lint commands in CLAUDE.md.
  • One task per session; /clear between unrelated tasks to keep context clean.
  • Worktrees for parallel sessions, so they never edit the same checkout.
  • Verify claims: ask what it ran and what the output was; "done" means a green check you can see.
  • Turn every correction into a rule in CLAUDE.md, a skill or a hook.

One we build: Persona

Persona is memory for AI coding agents: Penstock keeps what was asked, decided, refused and learned as plain files you own and, when memory is on, hands them to the model before it writes. It works with Claude Code over MCP. The persona that speaks from it is planned.

It is ours, so we are not neutral.

Levels: what to expect

1 Foundation

  • Run Claude Code in a repo; review and accept its changes
  • Write a useful CLAUDE.md with commands and rules
  • Use plan mode and permission prompts sensibly

2 Practitioner

  • Add hooks, skills, subagents and MCP servers for the team
  • Run headless and GitHub Action workflows
  • Use Cowork with plugins and connectors for knowledge work

3 Senior

  • Design an agent workflow with gates, reviewers and attempt limits
  • Govern permissions, secrets and sandboxing
  • Turn recurring corrections into skills and hooks

4 Expert

  • Set the organisation's agentic engineering practice
  • Build shared plugins and blueprints across teams
  • Measure productivity and quality impact

Each level includes the ones before it. See Start here for what the levels mean.
