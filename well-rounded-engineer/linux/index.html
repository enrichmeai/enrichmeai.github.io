Linux

The commands you need on a server, in a container, or in a CI runner. Networking commands live on the Networking tab.

Where things live

PathHolds
/etcsystem configuration
/var/loglogs (when not in the journal)
/var/libservice data (docker, postgres)
/tmptemporary files, often cleared on reboot (depends on the distribution)
/home, /rootuser homes
/usr/bin, /usr/local/binprograms; local installs go in /usr/local
/optself-contained third-party software
/proc, /syslive kernel and process information
/devdevices

Processes & signals

ps aux | grep java
ps -eo pid,ppid,%cpu,%mem,etime,cmd --sort=-%mem | head
pgrep -af gunicorn
top / htop                               # P cpu, M memory, k kill
kill PID                                 # SIGTERM: ask nicely
kill -9 PID                              # SIGKILL: cannot be caught, no cleanup
pkill -f 'python -m loader'
lsof -i :8080                            # who holds the port
lsof -p PID | wc -l                      # open files
nohup ./job.sh > job.log 2>&1 &          # survive logout
jobs; fg %1; bg; disown
timeout 300 ./slow.sh                    # kill after 5 min
nice -n 10 ./batch.sh                    # lower priority

Exit codes: 0 success; 1 general error; 126 not executable; 127 command not found; 128+N killed by signal N (137 = 128+9 SIGKILL, 143 = 128+15 SIGTERM).

Disk, memory, system

df -h                     # free space per filesystem
df -i                     # inodes: "no space" with free GB means inodes
du -xh / --max-depth=1 2>/dev/null | sort -h
free -h                   # "available" is what matters, not "free"
uptime                    # load average: compare with CPU count
nproc; lscpu; lsblk
vmstat 1 5                # run queue, swap, IO wait
iostat -x 1               # disk busy (sysstat)
dmesg -T | tail           # kernel: OOM killer, disk errors
uname -a; cat /etc/os-release
ulimit -n                 # max open files for this shell

Permissions & users

ls -l f        # -rwxr-x--- 1 app app ...  owner / group / others
chmod 640 f    # rw- r-- ---   (r=4 w=2 x=1)
chmod u+x run.sh
chmod -R g+rX dir/            # X: execute on dirs, and on files already executable
chown app:app f; chown -R 1001:1001 /data
id; whoami; groups
sudo -u app ./run.sh
sudo useradd -r -s /usr/sbin/nologin app     # service account, no login
umask                          # default permission mask

Private keys must not be accessible by others (use 600 or 400): ssh ignores a private key file that others can read. A directory needs x to be entered and r to be listed.

sudo systemctl restart nginx

Safe bash scripts

#!/usr/bin/env bash
set -euo pipefail          # stop on error, unset var, or failed pipe stage
IFS=$'\n\t'

usage() { echo "usage: $0 <env> <date>" >&2; exit 2; }
[[ $# -eq 2 ]] || usage
env="$1"; date="$2"
[[ "$env" =~ ^(dev|prod)$ ]] || { echo "bad env: $env" >&2; exit 2; }

tmp="$(mktemp -d)"
trap 'rm -rf "$tmp"' EXIT  # always clean up

log() { printf '%s %s\n' "$(date -u +%FT%TZ)" "$*" >&2; }

for f in data/*.csv; do
  [[ -e "$f" ]] || continue          # glob matched nothing
  log "loading $f"
done

# capture an exit code without dying under set -e
if ! out="$(some_command 2>&1)"; then
  log "failed: $out"; exit 1
fi
# shellcheck script.sh   ← run it

Quote every variable ("$f"). Unquoted values split on spaces and expand globs.

From Unix to Linux: a short history, with BSD and Solaris

The commands on this page are older than most of the people who type them. ls, pipes, “everything is a file” and the shell all come from Unix, started at Bell Labs in 1969. Knowing the family tree explains why Linux, macOS and the BSDs feel alike, and why a script written on one often runs on another.

WhenWhat happened
1960sBell Labs, MIT and General Electric build Multics, an ambitious time-sharing system. Bell Labs, frustrated by its size and complexity, pulls out.
1969At Bell Labs, Ken Thompson, Dennis Ritchie and colleagues start Unix, first written in assembly language for a PDP-7.
1973Version 4 Unix is rewritten in C, a high-level language. A system written in a high-level language can be moved to new machines far more easily, and Unix spreads.
1978The first BSD (Berkeley Software Distribution) release, from the University of California, Berkeley, after Thompson spent a sabbatical there installing Unix; Bill Joy led early development.
1983AT&T sells UNIX System V commercially. Richard Stallman announces the GNU Project, to build a complete free Unix-compatible operating system.
1988The first POSIX standard (IEEE 1003.1) defines a common interface, so programs can run on many Unix-like systems; its shell and tools are based on System V.
1991Linus Torvalds releases the Linux kernel on 17 September. GNU had the tools but no working kernel; together they make a complete free system.
1993Sun Microsystems’ Solaris, based on System V, replaces its BSD-based SunOS. Solaris becomes known for scaling on SPARC servers, and for originating DTrace and ZFS.
2005Sun releases most of Solaris as open source (OpenSolaris).
2007Apple’s Mac OS X 10.5 is certified as UNIX 03 compliant: macOS is a certified Unix.
2010Oracle buys Sun and discontinues OpenSolaris. The community continues it as illumos.
TodayLinux is the leading operating system on servers, and through Android has the largest installed base of any general-purpose operating system. Solaris is now Oracle Solaris, a proprietary Unix.
FamilyWhere you meet it now
Linux (a Unix-like kernel, with GNU and other tools)Cloud servers, containers, Android phones, Chromebooks (see Docker and Kubernetes)
BSD descendantsFreeBSD, OpenBSD and NetBSD; macOS’s kernel draws on Mach and BSD, and macOS is a certified Unix
Commercial UnixOracle Solaris, IBM AIX and HP-UX, still used in certain fields, often on dedicated hardware
Solaris’s open-source lineillumos; ZFS and DTrace also reached other systems

Our view: learn the Unix ideas, not one distribution’s quirks: small tools that do one thing, text streams joined by pipes, and files and permissions as the common language. They work on every system in the table, and POSIX is why. The other view: in practice most engineers now meet only Linux, in containers and cloud machines, so time is better spent on Linux specifics such as systemd, cgroups and the distribution your servers run.

Levels: what to expect

1 Foundation

  • Navigate, read and search files and logs
  • Run, stop and inspect processes
  • Understand permissions well enough to fix 'permission denied'

2 Practitioner

  • Write safe bash scripts with set -euo pipefail, traps and quoting
  • Diagnose disk, memory and CPU problems with df, free, top, dmesg
  • Manage services with systemd and read journalctl

3 Senior

  • Tune a host or container for a workload (file limits, memory, I/O)
  • Debug with strace, lsof and tcpdump
  • Decide when a script should become a real program

4 Expert

  • Understand kernel mechanisms behind containers (namespaces, cgroups)
  • Set the team's base images and hardening standards
  • Lead performance investigations end to end

Each level includes the ones before it. See Start here for what the levels mean.
