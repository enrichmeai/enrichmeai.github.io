Apigee

Google Cloud's API management platform: a gateway plus API products, developer apps, quotas, security policies, analytics and a developer portal. Background on gateways is on APIs & Integration.

Core concepts

ConceptMeaning
OrganisationTop-level Apigee container, tied to a GCP project
EnvironmentA runtime context where proxies are deployed (dev, test, prod)
Environment groupHostnames that route to one or more environments
API proxyThe façade clients call; it applies policies and forwards to the backend
Proxy endpointClient-facing side: base path, request and response flows
Target endpointBackend-facing side: the service URL, its auth and timeouts
FlowOrdered steps: PreFlow, conditional flows, PostFlow, on request and response
PolicyA reusable step: verify a key, check a token, rate-limit, transform, cache
Shared flowA reusable sequence of policies used by many proxies (security, logging)
API productA bundle of proxies and operations with quotas and scopes, offered to consumers
Developer / appA consumer and their registered app, which gets keys for products

Apigee X is the Google Cloud-hosted version; Apigee hybrid runs the runtime in your own Kubernetes clusters. Apigee Edge is the older generation.

Proxy endpoint

<!-- apiproxy/proxies/default.xml -->
<ProxyEndpoint name="default">
  <PreFlow name="PreFlow">
    <Request>
      <Step><Name>VK-VerifyKey</Name></Step>
      <Step><Name>SA-SpikeArrest</Name></Step>
      <Step><Name>Q-PerApp</Name></Step>
    </Request>
  </PreFlow>
  <Flows>
    <Flow name="search">
      <Condition>proxy.pathsuffix MatchesPath "/search" and request.verb = "GET"</Condition>
    </Flow>
  </Flows>
  <HTTPProxyConnection>
    <BasePath>/legal/v1</BasePath>
  </HTTPProxyConnection>
  <RouteRule name="default">
    <TargetEndpoint>default</TargetEndpoint>
  </RouteRule>
</ProxyEndpoint>

Target endpoint to Cloud Run

<!-- apiproxy/targets/default.xml -->
<TargetEndpoint name="default">
  <HTTPTargetConnection>
    <Authentication>
      <GoogleIDToken>
        <Audience>https://legal-api-xxxxx.a.run.app</Audience>
      </GoogleIDToken>
    </Authentication>
    <URL>https://legal-api-xxxxx.a.run.app</URL>
  </HTTPTargetConnection>
</TargetEndpoint>

Apigee calls the private Cloud Run service with a Google ID token from the proxy's service account, which needs roles/run.invoker. Clients never reach Cloud Run directly; set its ingress accordingly.

Common policies

<VerifyAPIKey name="VK-VerifyKey">
  <APIKey ref="request.header.x-api-key"/>
</VerifyAPIKey>

<OAuthV2 name="OA-VerifyToken">
  <Operation>VerifyAccessToken</Operation>
</OAuthV2>

<SpikeArrest name="SA-SpikeArrest">
  <Rate>30ps</Rate>               <!-- smooths bursts -->
</SpikeArrest>

<Quota name="Q-PerApp">
  <Interval>1</Interval>
  <TimeUnit>day</TimeUnit>
  <Allow count="10000"/>
  <Identifier ref="client_id"/>
</Quota>

<AssignMessage name="AM-RemoveKey">
  <Remove><Headers><Header name="x-api-key"/></Headers></Remove>
</AssignMessage>
CategoryPolicies
SecurityVerifyAPIKey, OAuthV2, VerifyJWT, BasicAuthentication, AccessControl, CORS
TrafficSpikeArrest, Quota, ResponseCache
MediationAssignMessage, ExtractVariables, JSONtoXML, XMLtoJSON, RaiseFault
ExtensionJavaScript, ServiceCallout, MessageLogging, FlowCallout (shared flows)

SpikeArrest protects the backend from bursts; Quota enforces each consumer's allowance. Use both.

Products, apps and keys

  1. Build a proxy and deploy it to an environment.
  2. Create an API product listing the proxy (and operations), environments, quota and scopes, e.g. "Legal Search – Standard: 10,000 calls/day".
  3. A developer registers an app and subscribes it to the product.
  4. The app gets a consumer key (and secret for OAuth). The proxy's VerifyAPIKey or OAuthV2 policy checks it and loads the product's quota.
  5. Analytics then report traffic, latency and errors per product, app and developer.

Products are how you package the same API differently: free and paid tiers, internal and partner access.

Apigee vs API Gateway

ApigeeAPI Gateway
ScopeFull API managementLightweight managed gateway
FeaturesProducts, developer portal, monetisation, rich policies, analytics, hybridOpenAPI-defined routes, API keys, JWT auth, quotas
BackendsAnything reachableCloud Run, Cloud Functions, App Engine and others
CostSignificant; subscription or pay-as-you-goLow, per call
Choose whenMany APIs, external consumers, governance, analyticsA few APIs, mostly internal or simple

Cloud Endpoints is the older Google option; new designs generally pick API Gateway or Apigee.

Delivering proxies like code

  • Keep the apiproxy/ bundle and shared flows in Git; review policy changes like code.
  • Deploy from CI with the Apigee API, apigeecli or the Apigee Maven plugin, to dev → test → prod environments.
  • Manage organisations, environments and environment groups with Terraform (google_apigee_* resources).
  • Lint bundles with apigeelint before deploying.
  • Use shared flows as your blueprint: one security and logging flow every proxy calls, instead of copied policies.
  • Test with the trace/debug tool, and with automated API tests against each environment.

Security and operations

  • Validate OAuth tokens or JWTs at the edge; the backend still checks object-level permissions.
  • Strip credentials before forwarding; add a trusted identity header only from Apigee.
  • Use Advanced API Security to detect abuse and misconfigured proxies.
  • Put Cloud Armor in front of the external load balancer for WAF and DDoS protection.
  • Log to Cloud Logging with MessageLogging; never log keys or tokens.
  • Watch latency split: total vs target response time tells you if the gateway or the backend is slow.

Levels: what to expect

1 Foundation

  • Explain proxies, policies, products and apps
  • Call an API through Apigee with a key
  • Read Apigee analytics for an API

2 Practitioner

  • Build a proxy with key/token verification, spike arrest and quota
  • Use shared flows; deploy through environments from CI
  • Connect securely to Cloud Run backends

3 Senior

  • Design API products, tiers and the developer portal
  • Run Apigee across environments with Terraform and CI
  • Secure APIs at the edge with OAuth and Advanced API Security

4 Expert

  • Own the organisation's API management platform and governance
  • Design hybrid or multi-region Apigee deployments
  • Lead API monetisation and partner programmes

Each level includes the ones before it. See Start here for what the levels mean.
