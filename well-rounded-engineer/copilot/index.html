GitHub Copilot

GitHub's AI assistant across the editor, the command line and github.com: completions, chat, agent mode, a coding agent that works on issues and opens pull requests, and code review. How to configure it for a team and how it compares with Claude Code.

Features

FeatureWhereDoes
Code completionsIDESuggests the next lines as you type
Copilot ChatIDE, github.com, mobileAnswers questions about code, explains, drafts changes
Agent modeIDE (e.g. VS Code)Plans and makes multi-file edits, runs commands and tests, iterates
Copilot coding agentgithub.comAssign it an issue; it works in a cloud environment and opens a draft PR for review
Copilot code reviewPull requestsRequested as a reviewer; leaves comments and suggestions
Copilot CLITerminalAgentic help in the shell
Model choiceChat and agentsSeveral model families, including Claude models, depending on plan and admin settings

GitHub Copilot (for developers) is a different product from Microsoft 365 Copilot (for Office documents and email). Plans and feature names change often; check GitHub's docs.

This repo is a Spring Boot 3 WebFlux service on Java 21.
- Tests: ./gradlew :api:test (unit), CI runs integration tests.
- Never call .block() on the request path.
- Errors go through GlobalExceptionHandler; no onErrorResume in controllers.
- Use JdbcClient; no new JPA entities.

Keep one source of truth: if Claude Code reads CLAUDE.md and Copilot reads its own file, generate one from the other or point both at a shared document, so the rules cannot drift apart.

Admin and governance

  • Policies at enterprise and organisation level: which features and models are allowed.
  • Content exclusion: paths or repositories Copilot must not use as context.
  • Public code filter: block suggestions matching public code, where licence risk matters.
  • MCP servers for agent mode and the coding agent, configured per repository or organisation.
  • Coding agent environment: a setup workflow, a firewall allow-list, and branch protections; its PRs go through normal review and CI.
  • Usage metrics for adoption and acceptance rates.

Copilot and Claude Code compared

GitHub CopilotClaude Code
HomeThe IDE and github.comThe terminal and repository (plus IDE, desktop, web)
StrengthsInline completions, tight GitHub integration (issues, PRs, review)Long, multi-step agentic tasks; deep customisation with hooks, skills and subagents
ConfigurationInstruction and prompt files, policiesCLAUDE.md, settings, hooks, skills, agents, plugins
Asynchronous workCoding agent on issuesCloud sessions, GitHub Action, headless mode

Many teams use both: completions while typing, an agent for whole tasks. The disciplines are the same: clear briefs, tests as the definition of done, human review, and rules written into the repo.

Using it responsibly

  • Review every suggestion; accepted code is your code.
  • Watch for invented APIs and outdated patterns; check official docs.
  • Keep secrets out of files Copilot can read; use content exclusion for sensitive paths.
  • Coding-agent PRs get the same CI, review and security checks as human PRs.
  • Prefer extending your frameworks to generating new boilerplate (Frameworks vs AI).

Levels: what to expect

1 Foundation

  • Use completions and chat; review every suggestion
  • Know the difference between GitHub Copilot and Microsoft 365 Copilot
  • Find and follow the repo's Copilot instructions

2 Practitioner

  • Write repository and path instructions and prompt files
  • Use agent mode and the coding agent on scoped issues
  • Request and act on Copilot code review

3 Senior

  • Configure policies, content exclusion and MCP for a team
  • Set up the coding agent environment and protections
  • Keep Copilot and Claude Code instructions consistent

4 Expert

  • Own AI-assisted development policy across the organisation
  • Evaluate tools and models with real task metrics
  • Lead adoption and training

Each level includes the ones before it. See Start here for what the levels mean.
