Kubernetes

Core objects, the kubectl you will use daily, manifests that hold up in production, and GKE specifics.

Core objects

KindUse it for
PodOne or more containers sharing network and volumes. Rarely created directly.
DeploymentStateless apps: keeps N replicas, rolling updates, rollback.
StatefulSetStable names and per-pod disks: databases, Kafka, ZooKeeper.
DaemonSetOne pod per node: log shippers, node agents.
Job / CronJobRun to completion, once or on a schedule: batch loads, migrations.
ServiceStable virtual IP and DNS name in front of matching pods.
Ingress / GatewayHTTP routing from outside into Services (Gateway API is the newer model).
ConfigMap / SecretConfiguration and credentials, as env vars or files.
PersistentVolumeClaimA request for durable storage.
ServiceAccountIdentity for pods (and, on GKE, the link to a Google service account).
HorizontalPodAutoscalerScale replicas on CPU, memory or custom metrics.
NetworkPolicyPod-level firewall rules.
NamespaceA scope for names, quotas and RBAC.

Deployment + Service

apiVersion: apps/v1
kind: Deployment
metadata: { name: api, labels: { app: api } }
spec:
  replicas: 2
  selector: { matchLabels: { app: api } }
  strategy: { rollingUpdate: { maxUnavailable: 0, maxSurge: 1 } }
  template:
    metadata: { labels: { app: api } }
    spec:
      serviceAccountName: api
      containers:
        - name: api
          image: asia-south1-docker.pkg.dev/my-proj/apps/api:3f2a9c1
          ports: [{ containerPort: 8080 }]
          envFrom: [{ configMapRef: { name: api-config } }]
          env:
            - name: DB_PASSWORD
              valueFrom: { secretKeyRef: { name: db, key: password } }
          resources:
            requests: { cpu: 250m, memory: 512Mi }
            limits:   { memory: 512Mi }
          readinessProbe:
            httpGet: { path: /actuator/health/readiness, port: 8080 }
            periodSeconds: 5
          livenessProbe:
            httpGet: { path: /actuator/health/liveness, port: 8080 }
            initialDelaySeconds: 20
          startupProbe:
            httpGet: { path: /actuator/health/liveness, port: 8080 }
            failureThreshold: 30
            periodSeconds: 2
---
apiVersion: v1
kind: Service
metadata: { name: api }
spec:
  selector: { app: api }
  ports: [{ port: 80, targetPort: 8080 }]

Job & CronJob

apiVersion: batch/v1
kind: CronJob
metadata: { name: corpus-load }
spec:
  schedule: "15 6 * * *"
  timeZone: "Etc/UTC"
  concurrencyPolicy: Forbid          # never two runs at once
  startingDeadlineSeconds: 600
  successfulJobsHistoryLimit: 3
  failedJobsHistoryLimit: 5
  jobTemplate:
    spec:
      backoffLimit: 0                # no automatic retries
      activeDeadlineSeconds: 3600
      ttlSecondsAfterFinished: 86400
      template:
        spec:
          restartPolicy: Never
          serviceAccountName: loader
          containers:
            - name: loader
              image: asia-south1-docker.pkg.dev/my-proj/apps/loader:3f2a9c1
              args: ["--year=2024"]
              resources: { requests: { cpu: "1", memory: 2Gi }, limits: { memory: 2Gi } }
kubectl create job --from=cronjob/corpus-load manual-20250131   # run now
kubectl get jobs; kubectl logs job/manual-20250131

Services & traffic

  • ClusterIP (default): reachable inside the cluster only.
  • NodePort: a port on every node (30000–32767). Mostly a building block.
  • LoadBalancer: provisions a cloud load balancer with an external (or internal, by annotation) IP.
  • Headless (clusterIP: None): DNS returns pod IPs directly; used with StatefulSets.
  • DNS name: <svc>.<namespace>.svc.cluster.local; within the same namespace just <svc>.
  • A Service with no endpoints means its selector matches no ready pod: check labels and readiness.
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata: { name: api }
spec:
  ingressClassName: nginx          # GKE's own controller uses the annotation kubernetes.io/ingress.class: gce instead
                                   # Ingress NGINX was retired in March 2026: prefer Gateway API or a maintained controller
  rules:
    - host: api.example.com
      http:
        paths:
          - path: /
            pathType: Prefix
            backend: { service: { name: api, port: { number: 80 } } }

kubectl get endpointslices -l kubernetes.io/service-name=api

Requests, limits, probes

  • Requests decide scheduling: the node must have that much free. Limits cap use.
  • Over the memory limit → the container is killed (OOMKilled, exit 137). Over the CPU limit → throttled, not killed.
  • Set memory request = limit for steady apps. Many teams leave the CPU limit off to avoid throttling.
  • JVM: size heap from the container with -XX:MaxRAMPercentage=75.
  • Readiness failing removes the pod from Service traffic. Liveness failing restarts it. Startup holds the other two off until the app has booted.
  • Never make liveness depend on a database or another service: an outage then restarts every pod.
  • QoS: Guaranteed (requests = limits for all), Burstable, BestEffort (none set; evicted first).

Debug by status

StatusUsually means
PendingNo node fits the requests, a PVC is unbound, or a node selector/taint excludes all nodes. describe pod → Events.
ImagePullBackOffWrong image name or tag, or the node's identity cannot read the registry.
CrashLoopBackOffThe app starts and exits. logs --previous shows why: bad config, missing secret, failed probe.
OOMKilledMemory limit too low, or a leak. Check describe → Last State.
CreateContainerConfigErrorA referenced ConfigMap or Secret key does not exist.
Running, not ReadyReadiness probe failing: wrong path or port, or a dependency is down.
EvictedNode ran short of memory or disk.

Config, secrets, scaling, safety

kubectl create configmap api-config --from-literal=DATASET=fdp --from-file=app.yml
kubectl create secret generic db --from-literal=password='...'   # base64, NOT encrypted
kubectl get secret db -o jsonpath='{.data.password}' | base64 -d

# HPA
kubectl autoscale deploy api --cpu-percent=70 --min=2 --max=10

# PodDisruptionBudget: keep capacity during node upgrades
apiVersion: policy/v1
kind: PodDisruptionBudget
metadata: { name: api }
spec:
  minAvailable: 1
  selector: { matchLabels: { app: api } }

# NetworkPolicy: default deny ingress in the namespace
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata: { name: default-deny-ingress }
spec:
  podSelector: {}
  policyTypes: [Ingress]

For real secrets use Secret Manager via the CSI driver or External Secrets, not values committed in YAML.

RBAC & GKE Workload Identity

# Pod's Kubernetes SA → Google service account (no JSON keys)
apiVersion: v1
kind: ServiceAccount
metadata:
  name: loader
  namespace: corpus
  annotations:
    iam.gke.io/gcp-service-account: dp-loader@my-proj.iam.gserviceaccount.com

gcloud iam service-accounts add-iam-policy-binding \
  dp-loader@my-proj.iam.gserviceaccount.com \
  --role=roles/iam.workloadIdentityUser \
  --member="serviceAccount:my-proj.svc.id.goog[corpus/loader]"

# RBAC: read-only on pods in one namespace
kubectl create role pod-reader --verb=get,list,watch --resource=pods -n corpus
kubectl create rolebinding jo-reads --role=pod-reader --user=jo@example.com -n corpus
kubectl auth can-i delete pods -n corpus --as=jo@example.com

GKE can also grant IAM roles straight to the Kubernetes principal (principal://iam.googleapis.com/projects/<number>/locations/global/workloadIdentityPools/<proj>.svc.id.goog/subject/ns/<ns>/sa/<ksa>) without a Google service account.

GKE, Helm, Kustomize

gcloud container clusters create-auto main --region=asia-south1   # Autopilot
gcloud container clusters get-credentials main --region=asia-south1
gcloud container clusters list

# Helm: packaged apps with values
helm install redis oci://registry-1.docker.io/bitnamicharts/redis \
  -n cache --create-namespace -f values.yaml     # check the chart's README for where its images come from
helm upgrade --install api ./chart --set image.tag=3f2a9c1
helm template ./chart | kubectl diff -f -
helm rollback api 1

# Kustomize: one base, overlays per env (built into kubectl)
k8s/base/kustomization.yaml       resources: [deploy.yaml, svc.yaml]
k8s/overlays/prod/kustomization.yaml
  resources: [../../base]
  images: [{ name: api, newTag: 3f2a9c1 }]
  patches: [{ path: replicas.yaml }]
kubectl apply -k k8s/overlays/prod

Autopilot: Google manages nodes and you pay per pod request. Standard: you manage node pools. For one-shot batch work, Cloud Run jobs are often simpler than a cluster.

Levels: what to expect

1 Foundation

  • Use kubectl to get, describe, log and exec
  • Read a Deployment and Service manifest
  • Explain why a pod is Pending or crashing

2 Practitioner

  • Write manifests with probes, resources and config
  • Use Helm or Kustomize per environment
  • Set up Workload Identity and RBAC

3 Senior

  • Design namespaces, network policies and autoscaling
  • Run production clusters: upgrades, PDBs, capacity
  • Debug networking, DNS and scheduling problems

4 Expert

  • Design multi-cluster platforms and tenancy models
  • Build operators and platform abstractions
  • Set Kubernetes strategy and security policy

Each level includes the ones before it. See Start here for what the levels mean.
