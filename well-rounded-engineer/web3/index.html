Web 3.0

"Web 3.0" means two different things. Web3 is the blockchain-based vision: decentralised ledgers, smart contracts, tokens and wallets. The Semantic Web (Tim Berners-Lee's earlier "Web 3.0") is about machine-readable, linked data. Both matter to engineers, for different reasons. The Solid tab covers Berners-Lee's current project for personal data.

Web3 building blocks

  • Blockchain: a replicated, append-only ledger agreed by consensus (proof of stake on Ethereum), without a central operator.
  • Wallet and keys: a private key controls an account; whoever holds the key controls the assets. Lost key, lost assets.
  • Smart contract: a program deployed on the chain (Solidity on Ethereum), public, and immutable unless designed to be upgradeable.
  • Tokens: fungible (ERC-20) and non-fungible (ERC-721 NFTs) assets defined by contracts.
  • Gas: fees paid for computation and storage on chain.
  • Layer 2 rollups: process transactions off the main chain and post proofs to it, for lower fees.
  • Oracles: bring outside data on chain, a trust point in themselves.
  • Decentralised storage: IPFS and similar address content by its hash.
  • DeFi and DAOs: financial services and organisations governed by contracts and token votes.

A minimal smart contract

// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

/// Records a document hash and who registered it, once.
contract DocumentRegistry {
    mapping(bytes32 => address) public registeredBy;
    event Registered(bytes32 indexed docHash, address indexed by);

    function register(bytes32 docHash) external {
        require(registeredBy[docHash] == address(0), "already registered");
        registeredBy[docHash] = msg.sender;
        emit Registered(docHash, msg.sender);
    }
}

Tooling: Foundry or Hardhat to build and test, ethers.js or viem to call contracts, a testnet before mainnet, and an external audit before holding real value. Deployed bugs are public and often permanent.

Do you need a blockchain?

  1. Do several parties need to write to shared data?
  2. Do they not trust each other, or any single operator?
  3. Is there no acceptable trusted intermediary (a database run by a neutral party, a regulator)?
  4. Is public, permanent, tamper-evident history worth the cost, latency and loss of privacy?

If any answer is no, a conventional database, an append-only ledger table, signed records or a timestamping service is simpler, cheaper and easier to correct.

Also weigh regulation: rules for crypto assets differ by country and change often (India, for example, taxes crypto transfers and has evolving rules). Personal data on an immutable public chain conflicts with deletion rights.

The Semantic Web and linked data

  • RDF: data as triples (subject, predicate, object), each named by a URI, so data from different sources joins up.
  • Vocabularies and ontologies: shared meanings (schema.org, Dublin Core, FOAF; OWL for formal ontologies).
  • Formats: Turtle, JSON-LD (linked data in ordinary JSON), RDF/XML.
  • SPARQL: the query language for RDF data and knowledge graphs.
  • Knowledge graphs: entities and relationships, used in search, AI grounding and data integration.
  • For legal data: standards such as Akoma Ntoso (XML for legislation and judgments) and the European Legislation Identifier give documents stable, linkable identities and structure.
<!-- JSON-LD with schema.org, embedded in a web page -->
<script type="application/ld+json">
{ "@context": "https://schema.org",
  "@type": "Legislation",
  "name": "Bharatiya Nyaya Sanhita, 2023",
  "legislationJurisdiction": "IN",
  "legislationDate": "2023-12-25" }
</script>
# SPARQL: judgments citing a given judgment
PREFIX ex: <https://example.org/legal#>
SELECT ?j ?date WHERE {
  ?j ex:cites <https://example.org/judgment/HPHC010001232024> ;
     ex:decisionDate ?date .
} ORDER BY DESC(?date)

Levels: what to expect

1 Foundation

  • Tell Web3 (blockchain) from the Semantic Web
  • Explain blockchains, wallets, smart contracts and tokens
  • Ask whether a problem really needs a blockchain

2 Practitioner

  • Write and test a simple smart contract on a testnet
  • Publish structured data with JSON-LD and schema.org
  • Query linked data with SPARQL

3 Senior

  • Assess security, cost, privacy and regulation of a Web3 design
  • Design knowledge graphs and ontologies for a domain
  • Integrate legal-document standards (Akoma Ntoso, ELI)

4 Expert

  • Set strategy on decentralised and linked-data technologies
  • Lead audits and governance for on-chain systems
  • Shape open data standards in a sector

Each level includes the ones before it. See Start here for what the levels mean.
