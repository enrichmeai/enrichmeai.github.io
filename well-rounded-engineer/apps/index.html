Apps: native or cross-platform?

Where app development is going, and the honest trade-offs between building once per platform and sharing code. See UI history for how we got here.

The options

ApproachWhat it isGood forWatch out for
Native, per platformSwift and SwiftUI on Apple platforms; Kotlin and Jetpack Compose on AndroidThe best platform feel, newest features first, the deepest device accessTwo codebases, two skill sets, features that drift apart
Shared logic, native UIKotlin Multiplatform: share business logic, keep each platform's own UI (or share UI too with Compose Multiplatform)Teams that want one copy of the rules but a native lookNewer tooling; you still need people who know each platform
One UI toolkit everywhereFlutter (Dart), which draws its own widgets from a single codebaseOne team shipping the same app to several platforms fastLooks the same everywhere unless you adapt it; a further language to learn
Web skills, native componentsReact Native: React and JavaScript or TypeScript, mapped to the platform's own UI building blocksTeams that already build for the web with ReactA bridge layer between JavaScript and native code to understand and upgrade
The web itselfProgressive web apps (installable, can work offline), or a web app inside a native shell (Capacitor)Reach, one codebase, no store review for every change (PWA)Device APIs and store presence vary by platform

How to choose

  • Start from the product, not the framework. Does it need the camera, sensors, background work, or the latest platform features on day one? That pushes towards native.
  • Count the people. One small team rarely keeps two native apps equal; a shared approach often wins there.
  • Share the rules, not necessarily the screens. Business logic and data code are the safest things to share; UI is where platforms differ most.
  • Try the web first if the app is mostly forms and content. A good responsive web app may be all you need. See Web Fundamentals.

Where it is going

  • Declarative UI everywhere: SwiftUI, Jetpack Compose, Flutter and React all describe what the screen should show and let the framework work out the changes.
  • Kotlin is Google's preferred language for Android (announced 7 May 2019), and Kotlin Multiplatform was declared stable in November 2023.
  • Sharing code is now a normal choice, not a compromise, for many apps; truly native work remains the right call for the most demanding ones.
  • There is no single way out. Each option trades reach, feel, cost and skills differently, and the answer can change as the app grows.

Levels: what to expect

1 Foundation

  • Explain native, cross-platform and web app options
  • Build and run a sample app on one platform
  • Know what an app store review involves

2 Practitioner

  • Ship a feature on one mobile platform, with tests
  • Share business logic across platforms
  • Build an installable, offline-capable web app

3 Senior

  • Choose an app architecture for a product and team
  • Design offline, sync and push notifications
  • Plan releases, versions and backwards compatibility

4 Expert

  • Own mobile and desktop strategy across products
  • Lead a move between app technologies
  • Set performance, accessibility and security standards for apps

Each level includes the ones before it. See Start here for what the levels mean.
