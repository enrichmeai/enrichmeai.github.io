Kotlin: concise, null-safe, on the JVM

Kotlin is a concise multiplatform language from JetBrains. It runs on the JVM beside Java, uses the same libraries, and adds null safety, data classes and coroutines. Learn Java first; Kotlin then reads as Java with the boilerplate taken away.

Where you meet it

  • Android apps, where it is widely used.
  • Server-side services with Spring Boot or Ktor, mixed freely with Java in one codebase.
  • Build scripts: Gradle's Kotlin DSL (build.gradle.kts).
  • Shared code across platforms with Kotlin Multiplatform.

The ideas that matter

  • Null safety: String can never be null; String? can, and the compiler makes you handle it with ?., ?: or a check.
  • Data classes: equals, hashCode, toString and copy for free.
  • Sealed types and when: the compiler checks you handled every case.
  • Extension functions: add behaviour to a type you do not own.
  • Coroutines: asynchronous code written like sequential code (the kotlinx.coroutines library).
  • Java interop: call Java and be called from it; watch nullability at the boundary, where Java types arrive as "platform types" the compiler cannot check.

A small program, and its test

Run with Maven or Gradle and the Kotlin plugin. This compiles and its tests pass on the JVM.

data class Order(val id: String, val pence: Int, val note: String? = null)

sealed interface Check {
    data class Ok(val pence: Int) : Check
    data class Invalid(val reason: String) : Check
}

fun validate(o: Order): Check = when {
    o.pence <= 0 -> Check.Invalid("order ${o.id} has no amount")
    else -> Check.Ok(o.pence)
}

// An extension function: adds behaviour to a type you do not own.
fun Int.asPounds(): String = "£%d.%02d".format(this / 100, this % 100)

fun main() {
    val orders = listOf(Order("a1", 1250, note = "gift"), Order("a2", 0), Order("a3", 499))
    val total = orders.map(::validate).filterIsInstance<Check.Ok>().sumOf { it.pence }
    println("total: ${total.asPounds()}")
    // Null safety: note is String?, so the compiler makes you handle null.
    orders.forEach { println("${it.id}: ${it.note?.uppercase() ?: "no note"}") }
}
import kotlin.test.Test
import kotlin.test.assertEquals
import kotlin.test.assertIs

class OrdersTest {
    @Test fun `zero amount is invalid`() { assertIs<Check.Invalid>(validate(Order("a2", 0))) }
    @Test fun `pence format as pounds`() { assertEquals("£17.49", 1749.asPounds()) }
}

Build and tools

  • Gradle with the Kotlin DSL is the most common build; Maven has a Kotlin plugin too.
  • Tests: kotlin.test on JUnit 5; MockK for mocks; Kotest if you like a specification style.
  • Style: ktlint or detekt in CI.
  • IDE: IntelliJ IDEA, from the same company, has the deepest support.

Common mistakes

  • !! everywhere: it turns a compile-time check back into a runtime crash. Handle the null instead.
  • Trusting Java types: a value from a Java method may be null even if you declared it non-null.
  • Blocking inside a coroutine: a blocking call ties up the thread; use a suspending API or the IO dispatcher.
  • Clever over clear: scope functions (let, apply, also) nested three deep are hard to read.

Levels: what to expect

1 Foundation

  • Read Kotlin code beside Java
  • Use null safety, data classes and when
  • Write and run a test with kotlin.test

2 Practitioner

  • Build a service in Kotlin with Spring Boot or Ktor
  • Handle Java interop and platform types safely
  • Use coroutines for asynchronous work

3 Senior

  • Design structured concurrency and cancellation
  • Mix Kotlin and Java in one codebase cleanly
  • Set style and lint rules for a team

4 Expert

  • Lead a Java-to-Kotlin migration
  • Share code across platforms with Kotlin Multiplatform
  • Teach idiomatic Kotlin and review for it
