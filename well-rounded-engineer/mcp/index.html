MCP: Model Context Protocol

An open protocol for giving AI applications access to tools and data through a standard interface. What it is, how to build and add an MCP server, how to call one from the API, and how to use MCP safely around a data pipeline.

What MCP is

Without MCP, every AI application needs custom integration code for every tool. With MCP, a tool or data source is wrapped once as an MCP server, and any MCP-capable client (Claude Code, Claude apps, IDEs, your own agent) can use it. Think of it as a standard port between models and systems.

ConceptMeaning
Host / clientThe AI application and its connection to a server
ServerA program exposing capabilities over MCP
ToolsFunctions the model can call (query a table, check a pipeline run)
ResourcesRead-only data the application can load into context (a file, a run record)
PromptsReusable prompt templates the server offers
Transport: stdioServer runs as a local process; messages over stdin/stdout
Transport: Streamable HTTPServer runs remotely over HTTP; authorisation with OAuth

A server in Python (FastMCP)

# pip install "mcp[cli]" google-cloud-bigquery
from mcp.server.fastmcp import FastMCP
from google.cloud import bigquery

mcp = FastMCP("pipeline-status")
bq = bigquery.Client()

@mcp.tool()
def latest_runs(run_date: str) -> list[dict]:
    """Latest state of every pipeline stage for a run date (YYYY-MM-DD)."""
    sql = """SELECT stage, state, objects_examined, objects_failed, event_ts
             FROM `my-proj.dp_control.v_pipeline_run_latest`
             WHERE run_date = @d ORDER BY stage"""
    cfg = bigquery.QueryJobConfig(query_parameters=[
        bigquery.ScalarQueryParameter("d", "DATE", run_date)])
    return [dict(r) for r in bq.query(sql, job_config=cfg).result()]

@mcp.resource("ledger://{run_date}")
def ledger(run_date: str) -> str:
    """The full event history for a run date, as text."""
    return format_events(read_events(run_date))

if __name__ == "__main__":
    mcp.run()                              # stdio by default
    # mcp.run(transport="streamable-http") # to serve over HTTP

The function name, type hints and docstring become the tool's name, schema and description. Write the docstring for the model: what it does, inputs, and what it returns. A TypeScript SDK exists with the same concepts.

Add it to Claude Code and test it

# local stdio server, shared with the team via .mcp.json in the repo
claude mcp add --scope project pipeline-status -- python mcp/pipeline_status.py

# remote server over HTTP
claude mcp add --transport http pipeline-status https://mcp.example.com/mcp

claude mcp list
# inside Claude Code: /mcp shows servers, status and tools

# interactive testing without a model
npx @modelcontextprotocol/inspector python mcp/pipeline_status.py
  • Project scope writes .mcp.json, so everyone on the repo gets the same server.
  • Keep credentials out of .mcp.json; servers read Application Default Credentials or environment variables.
  • Approve which tools may run without asking in Claude Code's permission settings.

Call MCP servers from the API

resp = client.beta.messages.create(
    model="claude-opus-5-5",
    max_tokens=16000,
    betas=["mcp-client-2025-11-20"],
    mcp_servers=[{"type": "url", "name": "pipeline",
                  "url": "https://mcp.example.com/mcp"}],
    tools=[{"type": "mcp_toolset", "mcp_server_name": "pipeline"}],
    messages=[{"role": "user", "content": "Summarise yesterday's pipeline run."}],
)

The MCP connector needs both halves: the server in mcp_servers and a matching mcp_toolset in tools. It reaches remote (HTTP) servers only; check the docs for authentication options and current beta name.

MCP and a data pipeline: four patterns

PatternWhat the MCP server exposesWho uses itRule
1. Pipeline observabilityRun records, stage states, freshness per source, failures with reasonsEngineers in Claude Code: "why did ODP_LOAD fail on 19-09?"Read-only. Reports UNKNOWN when it cannot read the ledger.
2. Governed warehouse accessTable catalog, schemas, a guarded query toolAnalysts and engineers asking questions in natural languageDry-run first, byte cap, allow-listed datasets, read-only service account
3. Data catalog and lineageTable descriptions, owners, upstream and downstream models (dbt manifest, Dataplex)Anyone changing a model: "what breaks if I rename this column?"Generated from the source of truth, never hand-maintained
4. LLM step inside the pipelineReference data or lookups the model needs while extracting or classifyingA pipeline job calling a model (e.g. extracting citations from judgments)Prefer plain tool calls or batch jobs; validate outputs; never let the model write to production tables directly

MCP sits beside the pipeline, not inside its critical path. The pipeline must run, record and alert without any AI involved; MCP makes it easier to ask questions about it.

A guarded BigQuery query tool

ALLOWED = {"dp_fdp", "dp_cdp", "dp_control"}
MAX_BYTES = 5 * 1024**3                       # 5 GiB per query

@mcp.tool()
def run_query(sql: str) -> dict:
    """Run a read-only GoogleSQL SELECT over the fdp, cdp and control datasets.
    Returns at most 200 rows. Fails if the query would scan more than 5 GiB."""
    if not sql.lstrip().lower().startswith(("select", "with")):
        return {"error": "only SELECT queries are allowed"}
    dry = bq.query(sql, job_config=bigquery.QueryJobConfig(
        dry_run=True, use_query_cache=False))
    datasets = {t.dataset_id for t in dry.referenced_tables}
    if not datasets <= ALLOWED:
        return {"error": f"datasets not allowed: {sorted(datasets - ALLOWED)}"}
    if dry.total_bytes_processed > MAX_BYTES:
        return {"error": f"would scan {dry.total_bytes_processed/1e9:.1f} GB; add filters"}
    job = bq.query(sql, job_config=bigquery.QueryJobConfig(maximum_bytes_billed=MAX_BYTES))
    rows = [dict(r) for r in job.result(max_results=200)]
    return {"rows": rows, "bytes_processed": job.total_bytes_processed}

The real protection is the service account: give it only dataViewer on those datasets and jobUser. The string checks are a convenience, not a security boundary.

Deploying a remote MCP server

  • Serve with Streamable HTTP and run it on Cloud Run with its own service account.
  • Require authentication: OAuth for user-facing clients (the MCP authorisation spec builds on OAuth 2.1), or Cloud Run IAM for internal callers.
  • Rate-limit and log every tool call with the caller's identity.
  • Version tools like an API: add new ones rather than changing behaviour under the same name.
  • Ready-made servers exist for many systems, for example Google's MCP Toolbox for Databases (BigQuery, Postgres and others). Review what they expose before connecting them.

Designing good MCP tools

  • Few, task-shaped tools ("pipeline status for a date") beat many thin wrappers over every API call.
  • Clear names and descriptions: the model chooses tools from them.
  • Typed, validated inputs with enums and formats where possible.
  • Compact outputs: summarise and paginate; huge results waste context.
  • Honest errors: return what failed and how to fix it; distinguish "no data" from "could not read".
  • Read-only by default; any write needs explicit human approval in the client.

Security

  • An MCP server runs with its own credentials: give it least privilege, as you would a service.
  • Only install servers you trust and have reviewed; a malicious server can return instructions that steer the model (tool poisoning).
  • Treat tool outputs as untrusted data in the model's context.
  • Never put secrets in tool descriptions, outputs or .mcp.json.
  • Audit tool calls; alert on unusual volume or failed authorisation.

Levels: what to expect

1 Foundation

  • Explain servers, clients, tools, resources and transports
  • Add an existing MCP server to Claude Code and use it
  • Know the security risks of untrusted servers

2 Practitioner

  • Build an MCP server with FastMCP and test it with the Inspector
  • Expose read-only pipeline or warehouse tools with guardrails
  • Share servers with a team via project configuration

3 Senior

  • Design task-shaped tool sets with honest errors and compact outputs
  • Deploy remote servers on Cloud Run with OAuth or IAM
  • Integrate MCP with data pipelines without putting it on the critical path

4 Expert

  • Set MCP standards, review and approval process for the organisation
  • Build shared MCP platforms over core data and systems
  • Contribute to the protocol ecosystem
