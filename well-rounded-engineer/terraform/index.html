Terraform on GCP

HCL with the google provider: the CLI, state, the resources a data platform needs, and how to change things safely. Version tags show when a feature arrived in Terraform.

CLI workflow

terraform init                       # providers + backend
terraform init -upgrade              # newer providers within constraints
terraform fmt -recursive
terraform validate
terraform plan -var-file=env/dev.tfvars -out=plan.tfplan
terraform show plan.tfplan           # read it before applying
terraform apply plan.tfplan          # applies exactly what you read
terraform plan -destroy

terraform plan -target=module.landing          # emergency only
terraform apply -replace=google_cloud_run_v2_job.loader
terraform output -json
terraform console                    # try expressions
terraform providers lock -platform=linux_amd64 -platform=darwin_arm64

validate checks syntax and types only. A missing optional module argument or a wrong IAM wiring shows up in a plan, not before.

Providers & backend

terraform {
  required_version = ">= 1.7"

    google = { source = "hashicorp/google", version = "~> 7.0" }   # pin the major version you have tested
  }
  backend "gcs" {
    bucket = "my-proj-tfstate"      # versioning on!
    prefix = "dataplatform"
  }
}

  project = var.project_id
  region  = var.region
  default_labels = { managed_by = "terraform", env = var.env }
}

Variables, locals, outputs

  type = string
  validation {
    condition     = contains(["dev", "prod"], var.env)
    error_message = "env must be dev or prod."
  }
}

  type = map(object({
    enabled = bool
    args    = optional(list(string), [])

  type      = string
  sensitive = true

  name_prefix = "dp-${var.env}"

count, for_each, dynamic

# for_each over a set or map: stable addresses by key (prefer over count)
resource "google_bigquery_dataset" "layer" {
  for_each   = toset(["odp", "fdp", "cdp"])
  dataset_id = "dp_${each.key}"
  location   = var.region
}
# reference: google_bigquery_dataset.layer["fdp"].dataset_id

# count for on/off
resource "google_cloud_scheduler_job" "tick" {
  count = var.clock_enabled ? 1 : 0
  ...
}
# reference: one(google_cloud_scheduler_job.tick[*].id)

# dynamic nested blocks
dynamic "env" {
  for_each = var.env_vars
  content {
    name  = env.key
    value = env.value
  }
}

# list of objects → map for for_each
for_each = { for t in var.tables : t.name => t }

With count, removing an item in the middle renumbers everything after it and Terraform destroys and recreates those resources.

BigQuery dataset & table

resource "google_bigquery_dataset" "fdp" {
  dataset_id                 = "dp_fdp"
  location                   = "asia-south1"
  delete_contents_on_destroy = false
  labels = { layer = "fdp" }
}

resource "google_bigquery_table" "judgment" {
  dataset_id          = google_bigquery_dataset.fdp.dataset_id
  table_id            = "fdp_judgment"
  deletion_protection = true
  require_partition_filter = true

  time_partitioning {
    type  = "MONTH"
    field = "decision_date"
  }
  clustering = ["court_code", "cnr"]

  schema = jsonencode([
    { name = "judgment_key",  type = "STRING", mode = "REQUIRED" },
    { name = "court_code",    type = "STRING" },
    { name = "cnr",           type = "STRING" },
    { name = "decision_date", type = "DATE" },
  ])
}

resource "google_bigquery_dataset_iam_member" "api_reader" {
  dataset_id = google_bigquery_dataset.fdp.dataset_id
  role       = "roles/bigquery.dataViewer"
  member     = "serviceAccount:${google_service_account.api.email}"
}

Tables that dbt builds should not also be declared here; two owners fight over the schema. Declare datasets and IAM, let dbt own its tables.

GCS bucket

resource "google_storage_bucket" "landing" {
  name                        = "${var.project_id}-landing"
  location                    = "ASIA-SOUTH1"
  storage_class               = "STANDARD"
  uniform_bucket_level_access = true
  public_access_prevention    = "enforced"
  force_destroy               = false

  versioning { enabled = true }

  lifecycle_rule {
    condition {
      age            = 90
      matches_prefix = ["tmp/"]
    }
    action { type = "Delete" }
  }
  lifecycle_rule {
    condition { age = 365 }
    action {
      type          = "SetStorageClass"
      storage_class = "COLDLINE"
    }
  }
}

Cloud Run job + Cloud Scheduler

resource "google_cloud_run_v2_job" "loader" {
  name     = "${local.name_prefix}-loader"
  location = var.region
  deletion_protection = false

  template {
    task_count = 1
    template {
      service_account = google_service_account.loader.email
      timeout         = "3600s"
      max_retries     = 0
      containers {
        image = var.loader_image          # pass a tag or digest, never :latest
        args  = ["--year=2024"]
        resources { limits = { cpu = "1", memory = "2Gi" } }
        env {
          name = "DB_PASSWORD"
          value_source {
            secret_key_ref {
              secret  = google_secret_manager_secret.db.secret_id
              version = "latest"
            }
          }
        }
      }
    }
  }
}

resource "google_cloud_scheduler_job" "daily" {
  name      = "${local.name_prefix}-daily"
  region    = var.region
  schedule  = "15 6 * * *"
  time_zone = "Etc/UTC"
  paused    = var.clock_paused
  http_target {
    http_method = "POST"
    uri = "https://run.googleapis.com/v2/projects/${var.project_id}/locations/${var.region}/jobs/${google_cloud_run_v2_job.loader.name}:run"
    oauth_token {
      service_account_email = google_service_account.scheduler.email
      scope                 = "https://www.googleapis.com/auth/cloud-platform"
    }
  }
}

The scheduler's service account needs roles/run.invoker (or run.developer for overrides) on the job.

IAM: member, binding, policy

# _member: adds ONE principal to ONE role. Safe, composable. Use this.
resource "google_project_iam_member" "loader_bq" {
  project = var.project_id
  role    = "roles/bigquery.jobUser"
  member  = "serviceAccount:${google_service_account.loader.email}"
}

# _binding: OWNS the member list for one role (removes anyone else)
# _policy:  OWNS the whole policy (removes everything else, can lock you out)

resource "google_service_account" "loader" {
  account_id   = "dp-loader"
  display_name = "Corpus loader job"
}

# Workload Identity Federation for GitHub Actions: no JSON keys
resource "google_service_account_iam_member" "gh_deploy" {
  service_account_id = google_service_account.deploy.name
  role               = "roles/iam.workloadIdentityUser"
  member = "principalSet://iam.googleapis.com/${google_iam_workload_identity_pool.gh.name}/attribute.repository/org/repo"
}

Never mix _policy or _binding with _member for the same role: they overwrite each other on every apply.

Refactor without destroying

# Bring an existing resource under management (1.5)
import {
  to = google_storage_bucket.landing
  id = "my-proj-landing"
}
# terraform plan -generate-config-out=generated.tf

# Rename / move into a module (1.1)
moved {
  from = google_cloud_run_v2_job.loader
  to   = module.jobs["land"].google_cloud_run_v2_job.this
}

# Stop managing, keep the real resource (1.7)
removed {
  from = google_bigquery_table.legacy
  lifecycle { destroy = false }
}

# CLI equivalents (no review step: prefer the blocks above)
terraform state list
terraform state show google_storage_bucket.landing
terraform state mv  'a.b' 'module.x.a.b'
terraform state rm  google_bigquery_table.legacy

lifecycle, checks, preconditions

resource "google_sql_database_instance" "corpus" {
  ...
  lifecycle {
    prevent_destroy       = true           # plan fails instead of destroying
    ignore_changes        = [settings[0].disk_size]   # autoresize owns it
    create_before_destroy = false
    precondition {
      condition     = var.env != "prod" || var.tier != "db-f1-micro"
      error_message = "prod needs a real tier."
    }
  }
}

# replace when something else changes (1.2)
lifecycle { replace_triggered_by = [terraform_data.image_rev] }

# check block: warns on every plan, never blocks (1.5)
check "landing_bucket_reachable" {
  data "google_storage_bucket" "l" { name = google_storage_bucket.landing.name }
  assert {
    condition     = data.google_storage_bucket.l.versioning[0].enabled
    error_message = "Landing bucket versioning is off."
  }
}

Safety checklist

  • Read every plan line that says destroy or -/+ (replace). A replaced database or bucket loses its data.
  • State bucket: versioning on, uniform access, only the deploy identity can write. State holds secrets in plain text.
  • One state per environment (separate prefix or project). Workspaces suit identical copies, not dev vs prod with different shapes.
  • Pin providers with ~> and commit .terraform.lock.hcl.
  • Images by tag or digest from a variable, never :latest, so a plan shows when the image moves.
  • No secrets in tfvars. Reference Secret Manager; mark variables sensitive.
  • Apply from CI with Workload Identity Federation, from a saved plan file.
  • Config is not state: after an apply, read the live resource to confirm it.

Levels: what to expect

1 Foundation

  • Run init, plan and apply; read a plan
  • Change a resource's arguments safely
  • Use variables and outputs

2 Practitioner

  • Write reusable modules with validation
  • Manage state in a remote backend; use moved and import blocks
  • Run Terraform from CI with keyless auth

3 Senior

  • Design module and state layout for many environments
  • Refactor live infrastructure without destroying it
  • Write terraform tests and policy checks

4 Expert

  • Own infrastructure-as-code standards for the organisation
  • Design org-wide landing zones and guardrails
  • Lead provider upgrades and large migrations

Each level includes the ones before it. See Start here for what the levels mean.
