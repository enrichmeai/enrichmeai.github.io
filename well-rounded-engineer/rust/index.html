Rust: memory safety without a garbage collector

Rust is a language for reliable and efficient software. Its ownership model and type system catch memory and thread-safety bugs at compile time, without a garbage collector, so it suits critical services, embedded devices and code that other languages call into.

Where you meet it

  • Performance-critical services and infrastructure: proxies, databases, storage engines.
  • Fast tools for other languages: Python's Polars and the ruff linter are written in Rust. See Data Libraries.
  • Systems and embedded code, and WebAssembly in the browser.
  • Security-sensitive code, where memory-safety bugs are the usual way in. See Security.

The ideas that matter

  • Ownership: each value has one owner; when the owner goes out of scope, the value is freed. No garbage collector, no manual free.
  • Borrowing: lend a value as &T (many readers) or &mut T (one writer), never both at once. The borrow checker enforces it.
  • No null, no exceptions: Option<T> for maybe-a-value, Result<T, E> for success-or-error, and ? to pass an error up.
  • Enums and match: the compiler checks every case is handled.
  • Traits: shared behaviour, like interfaces, resolved at compile time.
  • Fearless concurrency: the same rules stop data races from compiling.

A small program, and its tests

cargo run runs it; cargo test runs the two tests; cargo clippy reports no warnings. Note that orders is still usable after total(&orders), because total only borrowed it.

use std::fmt;

#[derive(Debug, Clone, PartialEq)]
struct Order {
    id: String,
    pence: u32,
}

#[derive(Debug, PartialEq)]
enum OrderError {
    Empty(String),
    TooLarge { id: String, pence: u32 },
}

impl fmt::Display for OrderError {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        match self {
            OrderError::Empty(id) => write!(f, "order {id} has no amount"),
            OrderError::TooLarge { id, pence } => write!(f, "order {id} is too large: {pence}"),
        }
    }
}

// Borrows the order (&Order): validating does not take ownership of it.
fn validate(o: &Order) -> Result<u32, OrderError> {
    match o.pence {
        0 => Err(OrderError::Empty(o.id.clone())),
        p if p > 1_000_000 => Err(OrderError::TooLarge { id: o.id.clone(), pence: p }),
        p => Ok(p),
    }
}

// The ? operator returns the first error to the caller instead of panicking.
fn total(orders: &[Order]) -> Result<u32, OrderError> {
    let mut sum = 0;
    for o in orders {
        sum += validate(o)?;
    }
    Ok(sum)
}

fn main() {
    let orders = vec![
        Order { id: "a1".into(), pence: 1250 },
        Order { id: "a3".into(), pence: 499 },
    ];
    match total(&orders) {
        Ok(sum) => println!("total pence: {sum}"),
        Err(e) => println!("error: {e}"),
    }
    // orders is still usable here: total only borrowed it.
    let valid: Vec<&Order> = orders.iter().filter(|o| validate(o).is_ok()).collect();
    println!("valid orders: {}", valid.len());
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn empty_order_is_an_error_not_a_panic() {
        let o = Order { id: "a2".into(), pence: 0 };
        assert_eq!(validate(&o), Err(OrderError::Empty("a2".into())));
    }

    #[test]
    fn total_stops_at_the_first_error() {
        let orders = vec![
            Order { id: "a1".into(), pence: 100 },
            Order { id: "a2".into(), pence: 0 },
        ];
        assert!(total(&orders).is_err());
    }
}

Build and tools

  • Cargo: build, test, dependencies (crates from crates.io) and benchmarks in one tool.
  • rustfmt formats, Clippy lints, rust-analyzer powers the editor.
  • The compiler's messages are unusually helpful: read them in full, they often contain the fix.

Common mistakes

  • Fighting the borrow checker with .clone() everywhere: it compiles, but hides the design question of who owns what.
  • unwrap() in production code: it panics on an error. Return a Result or handle it.
  • Reaching for unsafe to get past a compile error. It switches off the guarantees you chose Rust for.
  • Expecting to be fast at it in a week. The learning curve is real; it pays back in fewer production bugs.

Levels: what to expect

1 Foundation

  • Explain ownership and borrowing
  • Use Result, Option and match
  • Build and test with Cargo

2 Practitioner

  • Write a CLI or service in Rust
  • Use traits, iterators and error types well
  • Keep Clippy clean and the code formatted

3 Senior

  • Design with lifetimes and generics
  • Write async Rust and choose a runtime
  • Wrap unsafe or foreign code behind safe interfaces

4 Expert

  • Lead Rust adoption where safety and speed matter
  • Write libraries other languages call
  • Teach Rust and review for soundness

Each level includes the ones before it. See Start here for what the levels mean.
