Solid

Solid is a set of open specifications, led by Tim Berners-Lee, for putting people in control of their data. Each person keeps data in a Pod (a personal online data store) and grants apps access to it, instead of every app keeping its own copy. It uses ordinary web standards (HTTP, linked data, OpenID Connect), not a blockchain.

How Solid works

PieceIs
PodA personal data store on a Solid server, self-hosted or from a provider; organisations can run Pods for their users
WebIDA URI that identifies a person or agent, pointing to a profile document
Solid-OIDCAuthentication built on OpenID Connect: the user logs in with their identity provider; apps act on their behalf
Access controlWeb Access Control (WAC) or Access Control Policies (ACP): who may read, write, append or control each resource
ResourcesFiles and containers in the Pod, read and written over HTTP (GET, PUT, POST, PATCH, DELETE)
Linked dataStructured data stored as RDF (often Turtle) with shared vocabularies, so different apps understand the same data
NotificationsApps can subscribe to changes in resources

The key shift: apps and data are separated. A user can switch apps without losing data, and grant or revoke access per app or person.

Data in a Pod

# a public profile document (Turtle)
@prefix foaf: <http://xmlns.com/foaf/0.1/> .
@prefix solid: <http://www.w3.org/ns/solid/terms#> .

<#me> a foaf:Person ;
  foaf:name "Asha Rao" ;
  solid:oidcIssuer <https://login.example-provider.com> .
# read it over plain HTTP
curl -H "Accept: text/turtle" https://asha.pod.example/profile/card
# Web Access Control: owner has full control of a folder
@prefix acl: <http://www.w3.org/ns/auth/acl#> .
<#owner> a acl:Authorization ;
  acl:agent <https://asha.pod.example/profile/card#me> ;
  acl:accessTo <./> ; acl:default <./> ;
  acl:mode acl:Read, acl:Write, acl:Control .

An app reading from a Pod (JavaScript)

import { login, handleIncomingRedirect, getDefaultSession, fetch }
  from "@inrupt/solid-client-authn-browser";
import { getSolidDataset, getThing, getStringNoLocale }
  from "@inrupt/solid-client";

await handleIncomingRedirect();
if (!getDefaultSession().info.isLoggedIn) {
  await login({ oidcIssuer: "https://login.example-provider.com",
                redirectUrl: window.location.href, clientName: "Case Notes" });
}

const profileUrl = "https://asha.pod.example/profile/card";
const dataset = await getSolidDataset(profileUrl, { fetch });   // authenticated fetch
const me = getThing(dataset, profileUrl + "#me");
const name = getStringNoLocale(me, "http://xmlns.com/foaf/0.1/name");

Libraries: Inrupt's JavaScript client libraries, and others for Java and Python. Servers: the open-source Community Solid Server for development and research; commercial servers for production.

Where it fits

  • Personal data that many services need: health records, education credentials, identity documents, preferences.
  • Public-sector data sharing with citizen consent; some governments are piloting or running Solid-based services.
  • Portability: users switch apps without exporting and importing.
  • Consent you can audit: access is granted per resource and can be revoked.

Challenges: app ecosystem still small, linked-data skills are less common, querying across many Pods is slower than a central database, and Pod providers must be trusted to run storage well.

One we build: Cistern

Cistern is a self-hostable data pod with an MCP server: every request from an AI agent is checked against your rules when it is made, never from a cache, and gets a receipt naming the rule that decided it. Its README describes it as an open Solid pod server. It is open source (Apache 2.0).
